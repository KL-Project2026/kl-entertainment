# 🚚 KL Project — Replit Agent 이전 준비 프롬프트

> **사용법**: 아래 전체를 Replit Agent에게 한 번에 던집니다. Phase 단위로 실행하고, 각 Phase 완료마다 변경 파일/검증 결과를 보고하도록 지시되어 있습니다.

---

## 0. 컨텍스트 (Replit Agent 에게)

당신은 **KL Project**의 Replit Agent 입니다. KL Project 는 KL Entertainment Group 의 멀티 지점 KTV (가라오케) 비즈니스 통합 관리 플랫폼입니다.

이 프로젝트를 곧 **로컬 VS Code + Claude Code 환경** 으로 이전합니다. 이전 후 인프라:

| 영역 | 이전 후 |
|---|---|
| API 서버 (`artifacts/api-server`, port 8080) | **Railway** |
| 프론트엔드 (`artifacts/web-app`) | **Vercel** |
| 데이터베이스 (PostgreSQL 16.10) | **Supabase** (pooler 6543) |
| 로컬 개발 | `./dev.sh` 다중 포트 동시 기동 |
| 도구 | **VS Code + Claude Code** (Conventional Commits, Sydney/Bangkok timezone) |

당신의 임무는 **Replit 환경에서 빠지기 전에** 코드베이스를 새 인프라 호환 상태로 만들고 동결하는 것입니다. 실제 Railway/Vercel/Supabase 배포는 다음 단계에서 수행합니다.

## 1. 절대 원칙 — Add Only Rule

이 프로젝트는 운영 시스템입니다. 다음을 위반하면 작업을 즉시 중단하세요:

1. ✅ **추가만, 삭제 금지** — 기존 파일/함수/엔드포인트는 그대로 보존. Replit 호환을 위한 코드도 `process.env.REPL_ID` 가드로 살려 둡니다.
2. ✅ **MIGRATION 주석 필수** — 새/수정 코드에 다음 주석 패턴:
   ```
   // MIGRATION: Replit-specific behavior preserved via env guard
   // MIGRATION: env-based API base for Railway+Vercel split
   ```
3. ✅ **데이터 모델 동결** — 53 개 테이블, Drizzle 스키마, 외래키 그래프 변경 0%. 마이그레이션 스크립트만 추가 가능.
4. ✅ **API 시그니처 동결** — 35 개 라우트의 입출력 스키마, HTTP 메서드, 경로 모두 동일.
5. ✅ **Socket.io 이벤트명 동결** — 룸보드/호스티스 가용성 실시간 이벤트는 SignalR 이전 시 1:1 매핑 필요.
6. ✅ **JWT 페이로드 구조 동결** — `kl-auth-storage` 호환성. 클레임 추가는 OK, 기존 클레임 제거/타입 변경은 NO.
7. ✅ **검증 가능한 변경** — 각 Phase 완료 후 회귀 테스트 결과 보고.

## Phase 1 · 빌드 시스템 Railway 호환화

### 1-1. `artifacts/api-server/build.mjs` 단순화

```js
// MIGRATION: Railway 단독 빌드 — esbuild only, no SPA bundle, no pg_dump
import { build } from 'esbuild';

await build({
  entryPoints: ['src/index.ts'],
  outfile: 'dist/index.cjs',
  bundle: true,
  platform: 'node',
  target: 'node24',
  format: 'cjs',
  // ESM-only deps (e.g. node-fetch v3, pino v9) → CJS require 호환 banner
  banner: {
    js: `
      const { createRequire } = await import('module');
      const require = createRequire(import.meta.url);
    `,
  },
  external: ['pg-native'],
  sourcemap: true,
});
```

## Phase 2 · 프론트엔드 Vercel 호환화

### 2-1. `artifacts/web-app/vite.config.ts` 수정

```ts
// MIGRATION: Replit 플러그인 lazy load — Vercel 빌드 환경에는 미설치
const replitPlugins = process.env.REPL_ID
  ? await (async () => {
      try {
        const errMod = await import('@replit/vite-plugin-runtime-error-modal');
        return [errMod.default()];
      } catch {
        return [];
      }
    })()
  : [];

// MIGRATION: PORT/BASE_PATH throw 제거 — Vercel 표준 환경변수만
const PORT = Number(process.env.PORT ?? 5173);
const BASE_PATH = process.env.BASE_PATH ?? '/';

export default defineConfig({
  base: BASE_PATH,
  plugins: [react(), ...replitPlugins],
  server: { port: PORT, host: '0.0.0.0' },
  build: { outDir: 'dist', sourcemap: true },
});
```

### 2-2. `lib/api-client-react/src/client.ts` (또는 동등 파일)

```ts
// MIGRATION: 환경변수 기반 API base — Replit 동일 origin → Railway 절대 URL
const API_URL = (import.meta.env.VITE_API_URL ?? '').replace(/\/$/, '');
const SOCKET_URL = import.meta.env.VITE_SOCKET_URL ?? API_URL;

export const apiBase = (path: string) => `${API_URL}${path}`;

// fetch wrapper — Cookie 인증 유지
export const apiFetch = (path: string, init?: RequestInit) =>
```

## Phase 3 · 백엔드 환경변수 / Supabase 호환

### 3-1. Supabase Pooler self-signed cert 수용

`artifacts/api-server/src/db/index.ts` (또는 db 연결 파일):

```ts
// MIGRATION: Supabase pooler self-signed cert 수용
const isSupabase = process.env.DATABASE_URL?.includes('supabase');
const ssl = isSupabase
  ? { rejectUnauthorized: false }
  : process.env.NODE_ENV === 'production'
    ? true
    : undefined;
```

### 3-2. ALLOWED_ORIGINS CORS 설정

`src/index.ts` (Express 미들웨어):

```ts
// MIGRATION: 다중 origin 지원 — Vercel 다중 도메인 대응
const allowedOrigins = (process.env.ALLOWED_ORIGINS ?? '')
  .split(',')
  .map(s => s.trim())
  .filter(Boolean);

app.use(cors({
  origin: (origin, cb) => {
    if (!origin || allowedOrigins.includes(origin)) return cb(null, true);
    cb(new Error(`Origin ${origin} not allowed`));
  },
  credentials: true,
}));
```

### 3-3. Cookie 도메인 / SameSite

JWT cookie 발급부:
```ts
res.cookie('kl-auth', token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: process.env.NODE_ENV === 'production' ? 'none' : 'lax',
  domain: process.env.COOKIE_DOMAIN, // .klproject.com
  maxAge: 7 * 24 * 60 * 60 * 1000,
});
```

크로스 사이트 (api.* ↔ app.*) 시 `sameSite: 'none' + secure: true` 필수.

## Phase 6 · 로컬 개발 스크립트 `dev.sh`

루트에 `dev.sh` 생성:

```bash
#!/usr/bin/env bash
# MIGRATION: 로컬 다중 서비스 동시 기동 (Replit 후속 환경)
set -euo pipefail

API_PORT="${API_PORT:-8080}"
WEB_PORT="${WEB_PORT:-5173}"

echo "🚀 KL Project local dev"
echo "   API:  http://localhost:${API_PORT}"
echo "   Web:  http://localhost:${WEB_PORT}"

# API 서버
(cd artifacts/api-server && PORT="${API_PORT}" pnpm dev) &
API_PID=$!

# Web App
(cd artifacts/web-app && PORT="${WEB_PORT}" pnpm dev) &
WEB_PID=$!

cleanup() {
  echo "🛑 Stopping..."
  kill "${API_PID}" "${WEB_PID}" 2>/dev/null || true
}
trap cleanup EXIT INT TERM

wait
```

`chmod +x dev.sh` 후 README 에 사용법 추가:
```bash
cp .env.example .env  # 값 채우기
pnpm install
./dev.sh
```
